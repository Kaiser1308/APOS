# APOS v3 – Đợt 3: Khoá test, kiểm kê test, phạm vi – Kế hoạch

> **Cho worker:** TDD từng task, `npm run check` xanh và commit ở cuối mỗi task. Commit đầu chép file này vào `docs/superpowers/plans/2026-11-23-apos-v3-dot3.md`. Kế hoạch sai ở chỗ đổi hành vi thì hỏi Lead.

**Goal:** Test chấp nhận do một agent riêng viết, nộp trước khi có code, phải đỏ vì đúng lý do, rồi bị khoá. Gate của mỗi gói chứng minh ba điều: test đã khoá không bị sửa và xanh; không test nào bị mất hay bị skip; không file nào bị sửa ngoài phạm vi. Ngoại lệ (file nhạy cảm, test bị bớt assert) phải có người duyệt và được ghi vào log.

**Architecture:**
- Goal có thêm trạng thái `testing`, nằm giữa lúc kế hoạch được nhận và lúc bắt đầu code.
- Khoá test là sự kiện `tests-locked`: hash từng file test, số assert của từng file, và bảng nối tiêu chí với test.
- Gate gói gọi ba hàm kiểm mới: `lockedTests`, `inventory`, `scope`.
- Mọi thứ phụ thuộc ngôn ngữ (đường dẫn test, mẫu assert, mẫu "chưa làm", mẫu lỗi nạp) lấy từ setup đã ghim. Setup lấy chúng từ danh mục khi draft.

**Spec:** `docs/superpowers/specs/2026-11-22-apos-v3-design.md` mục 5 (2b, 3), 6.3, 6.4, 6.5, 7.3. Nền: đợt 1 (PR #38) và đợt 2 (PR #39).

## Global Constraints

- Goal **không có setup v2 đã duyệt** thì bỏ qua khâu `testing`, chạy như đợt 1–2, và `goal show` ghi "không có khoá test". Không được làm hỏng luồng này.
- Không thêm runtime dependency.
- Log cũ (legacy) và Goal tạo ở đợt 1–2 vẫn replay được.
- Agent được duyệt thay các ngoại lệ ở spec 7.3, nhưng `by` phải ghi `agent:<tên>`. Lệnh duyệt của anh dùng `confirmHuman`.
- Đếm assert là kiểm tra thô (regex theo dòng). Tài liệu phải nói rõ điều này.

## Review Focus

1. **Test xanh ngay lúc khoá** (stub vô tình đã làm đúng, hoặc test không gọi vào stub): `tests submit` từ chối và nêu tên test.
2. **Test đỏ vì lỗi nạp hay lỗi cú pháp** (khớp `loadErrorPatterns`, hoặc mọi testcase là `error` không khớp `notImplementedPatterns`): bị từ chối, không tính là đỏ hợp lệ.
3. **Gói rẽ nhánh từ base cũ, không chứa commit đã khoá test:** submit bị từ chối với hướng dẫn rebase.
4. **Đổi tên một test đã khoá** trong lần sửa sau khoá: coi như xoá test, nên cần duyệt ngoại lệ, không được tự khoá lại.
5. **Diff của gói sửa file test đã khoá** (dù chỉ khoảng trắng): gate đỏ `locked test modified: <path>`, không cho qua bằng cách khác.

### Task 1: Hợp đồng: kiểu bằng chứng, đường dẫn, cửa công khai

**Files:** `src/domain/contracts.ts`, `src/domain/packages.ts`, `src/domain/plan.ts`, test đi kèm

**Interfaces:**
- Tiêu chí chấp nhận thêm: `proof: 'red-green' | 'stays-green' | 'manual'`, mặc định `red-green` (đợt 4 sẽ thêm `benchmark`, `scan`), và tuỳ chọn `given`, `when`, `then: string`.
- Gói việc (Multi-WP) thêm `paths: string[]` (glob, ≥ 1) và `stubPaths: string[]` (file khung rỗng của các cửa trong `interfaces`).
- Solo: `proposal` thêm `paths`, `stubPaths` và `entries: string[]` (cửa công khai); `WP-MAIN` nhận chúng.
- `lead commit` kiểm: mọi tiêu chí `red-green` hay `stays-green` thuộc đúng một gói; `paths` của các gói chồng nhau thì mỗi đường dẫn chung phải có trong `sharedPaths`.
- Goal tạo trước đợt 3 thì không bắt buộc các trường mới.

### Task 2: Setup: đường dẫn test và các mẫu

**Files:** `src/domain/project-setup.ts`, `src/domain/catalog.ts`, `catalog/*.json`, `src/app/setup-draft.ts`, test đi kèm

**Interfaces:**
- `PartSetup` thêm `tests: { paths: string[]; assertPatterns: string[]; notImplementedPatterns: string[]; loadErrorPatterns: string[] }`.
- Draft chép các mẫu này từ danh mục. Danh mục thêm `testPaths` cho mỗi stack (Python `tests/**`, `**/test_*.py`; TS `**/*.test.ts`, `**/*.spec.ts`, `tests/**`; Java `src/test/**`).
- Probe kiểm mọi regex biên dịch được.

### Task 3: `apos tests submit` và khoá test

**Files:** Create `src/app/test-lock.ts`, `src/domain/test-lock.ts`, `src/cli/commands/tests.ts`; Modify `src/domain/transitions.ts`; test đi kèm

**Interfaces:**
- Trạng thái Goal: `proposal-approved` chuyển sang `testing` khi Goal ghim setup v2, không thì sang `executing` như cũ. `tests-locked` chuyển `testing` sang `executing`.
- CLI: `apos tests submit <goalId> --commit <sha> [--by <name>]`. Bảng nối tiêu chí với test nằm trong commit, ở `.apos/goals/<id>/tests.json`, có dạng `[{acceptanceId, part, layer: 'L2'|'L3'|'L4', testIds: string[]}]`.
- `submitTests(goalId, commit, by): Promise<{ ok: boolean; problems: string[] }>`. Kiểm theo thứ tự, báo **mọi** lỗi cùng lúc:
  1. commit chứa `proposal.baseCommit`;
  2. diff từ base chỉ chạm file khớp `tests.paths` của các phần, file trong `stubPaths`, và `tests.json`;
  3. mọi tiêu chí `red-green` và `stays-green` có ít nhất một test;
  4. mỗi test id có trong báo cáo khi chạy lớp đã khai ở commit đó (test có nạp được);
  5. `red-green`: test `fail`, hoặc `error` khớp `notImplementedPatterns`; không khớp `loadErrorPatterns` (Review Focus 1, 2);
  6. `stays-green`: test `pass`;
  7. chạy 2 lần cho cùng kết quả.
- Đạt thì ghi `tests-locked { commit, files: Record<path, sha256>, asserts: Record<path, number>, map }`. Trượt thì không ghi gì, chỉ in lỗi.
- `apos tests show <goalId>` in commit đã khoá, số test theo lớp, và bảng nối.

### Task 4: Gate gói: test đã khoá, kiểm kê, phạm vi

**Files:** Create `src/domain/assurance.ts`; Modify `src/app/gate-service.ts`, `src/app/package-service.ts`; test đi kèm

**Interfaces:**
- Base của gói đổi thành commit trong `tests-locked` mới nhất. Commit submit phải chứa commit đó (Review Focus 3).
- `lockedTestsCheck(lock, deliveryFiles): CheckResult`: file nào trong `lock.files` khác hash là đỏ, `locked test modified: <path>` (Review Focus 5). Test trong map của các tiêu chí thuộc gói phải `pass` trên delivery; kết quả lấy từ lần chạy lớp đầy đủ, không chạy `runOne` từng test.
- `inventoryCheck(baseTests, deliveryTests, addedLines, forbid): CheckResult`: lấy các id `pass`/`fail` ở base (commit đã khoá) cộng các id ở L1. Id nào thiếu hoặc chuyển sang `skip` trên delivery là đỏ. Mẫu `forbid` xuất hiện trong dòng thêm mới cũng là đỏ.
- `scopeCheck(changed, pkgPaths, needsHuman, lockedFiles): CheckResult`: file ngoài `paths` là đỏ; file khớp `needsHuman` cho `needs-human`.
- Ba check ghi `checkId` lần lượt `APOS-LOCKED`, `APOS-INVENTORY`, `APOS-SCOPE`, cạnh `APOS-PROTECTED`.
- Cảnh báo `reviewReasons` của đợt 1 về việc đổi test bỏ đi khi Goal có khoá test; các cảnh báo khác giữ nguyên.

### Task 5: Duyệt ngoại lệ

**Files:** Create `src/app/exceptions.ts`; Modify `src/cli/commands/package.ts`, `src/app/inbox.ts`, `src/domain/transitions.ts`; test đi kèm

**Interfaces:**
- `apos exception approve <goalId> --kind needs-human|tests-weakened|floor-reduced --ref <packageId|commit> --reason <text> (--by agent:<tên> | --human [--on-behalf <text>])`. `floor-reduced` để dành cho đợt 4: schema có, chưa có luồng nào dùng tới.
- `--human` đi qua `confirmHuman`. `--by agent:<tên>` không cần xác nhận, nhưng chỉ dùng được cho các loại ở cột "agent duyệt thay" của spec 7.3.
- Ghi sự kiện `exception-approved { kind, ref, commit, reason, by }`.
- Gói `needs-human` vì file nhạy cảm: có ngoại lệ trùng commit thì submit lại sẽ tính là `green`, gate không chạy lại nếu commit không đổi.
- Inbox liệt kê các ngoại lệ đang chờ duyệt.

### Task 6: Sửa test đã khoá

**Files:** `src/app/test-lock.ts`, `src/cli/commands/tests.ts`, test đi kèm

**Interfaces:**
- `apos tests revise <goalId> --commit <sha> --reason <text> [--by]`. Commit phải chứa commit đã khoá trước, và chỉ chạm các loại file như ở Task 3.
- Kiểm lại toàn bộ Task 3 ở commit mới, cộng thêm:
  - mọi test id đã khoá vẫn còn (Review Focus 4);
  - mỗi tiêu chí vẫn có ít nhất số test như trước;
  - với từng file, `asserts[path]` mới ≥ cũ.
- Đạt hết thì ghi `tests-locked` với `revisionOf`.
- Thiếu id, hoặc số assert giảm, thì ghi `tests-revision-pending`, Goal hiện mục chờ trong inbox. Có `exception-approved kind=tests-weakened` trùng commit thì ghi `tests-locked`.
- Gói đang làm phải chứa commit khoá mới nhất mới submit được.

### Task 7: Luồng trọn vẹn và tài liệu

**Files:** `src/e2e/v3-flow.test.ts`; `.apos/skills/` (thêm vai `tester`: viết test chấp nhận từ Cho trước/Khi/Thì, chỉ gọi qua cửa đã khai, nộp kèm stub và `tests.json`; sửa `lead` và `worker`: base là commit đã khoá, cấm sửa test đã khoá); `README.md`; `docs/setup.md` (đường dẫn test và các mẫu); `docs/fault-injection.md` (ca cho Review Focus 1–5); `src/app/init-project.ts` (vai mới trong `ROLES`)
