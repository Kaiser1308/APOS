# APOS v3 – Đợt 4: Lớp theo khâu, sàn, luật kích hoạt, bằng chứng phi chức năng, bảng mức bảo đảm – Kế hoạch

> **Cho worker:** TDD từng task, `npm run check` xanh và commit ở cuối mỗi task. Commit đầu chép file này vào `docs/superpowers/plans/2026-11-23-apos-v3-dot4.md`. Kế hoạch sai ở chỗ đổi hành vi thì hỏi Lead.

**Goal:** Gate chạy đúng các lớp test của từng khâu. Các lớp đó là sàn của setup, cộng lớp Lead thêm cho gói, cộng lớp mà luật kích hoạt đòi; bớt sàn phải có người duyệt. Yêu cầu phi chức năng có bằng chứng bằng benchmark hoặc bằng quét. Mỗi Goal có một bảng mức bảo đảm, nói rõ cái gì máy chứng minh, cái gì anh xác nhận tay, ai duyệt thay chỗ nào, và cái gì đang tắt.

**Architecture:**
- Một hàm thuần `planLayers(setup, goal, pkg, stage, changed): LayerRun[]` quyết định chạy gì.
- `GateService` chạy theo kết quả của hàm đó, ở ba khâu: `submit`, `integrate`, `close`.
- Bảng mức bảo đảm là một read-model suy ra từ log. `goal show`, UI và tài liệu Goal ở các mốc đều dùng chung read-model này.

**Spec:** `docs/superpowers/specs/2026-11-22-apos-v3-design.md` mục 5, 6.2, 6.3, 6.5, 6.9, 7.3. Nền: đợt 1–3 (PR #38, #39, #40).

## Global Constraints

- Lõi không biết tên công cụ nào. Mọi lệnh lấy từ setup đã ghim.
- Goal không có setup v2 vẫn chạy như trước, và bảng ghi "không có setup".
- Không thêm runtime dependency.
- Mặc định của sàn (spec 6.2): `submit: [L0, L1, L2]`, `integrate: [L1, L2, L3]`, `close: [L0, L1, L2, L3, L4, L5]`. L6 là check `manual`.
- Lead chỉ được **thêm** lớp. Bớt lớp sàn cần `exception approve --kind floor-reduced`; agent được duyệt thay (spec 7.3), và việc duyệt thay hiện trên bảng.

## Review Focus

1. **Lớp sàn hay lớp kích hoạt chưa có test ở khâu đó** (ví dụ luật đòi e2e mà ở 2b không ai viết): kết quả `unverifiable`, nêu tên lớp. Tuyệt đối không coi là xanh.
2. **Lead thêm một lớp không có trong setup:** `lead commit` từ chối và nêu tên lớp.
3. **Benchmark dao động quanh ngưỡng:** chạy `runs` lần (mặc định 3), kết quả các lần lệch nhau thì `unverifiable`. Không lấy lần tốt nhất.
4. **Quét SARIF ra finding mức thấp hơn mức chặn:** không đỏ, nhưng ghi số finding lên bảng.
5. **Gate tích hợp Multi-WP:** phải chạy lớp của khâu `integrate` trên commit tích hợp. Hiện nó chưa chạy lớp nào (worker đợt 3 đã báo).

### Task 1: `planLayers`

**Files:** Create `src/domain/layer-plan.ts`, kèm test

**Interfaces:**
```ts
type Stage = 'submit' | 'integrate' | 'close';
type LayerRun = { part: string | 'system'; layer: LayerId; tool: LayerSpec; why: 'floor' | 'lead' | 'trigger' | 'goal-flag'; reduced?: boolean };
function planLayers(input: { setup: ProjectSetup; stage: Stage; changed: string[]; packageLayers?: Partial<Record<Stage, LayerId[]>>; goalFlags: string[]; reductions: { stage: Stage; layer: LayerId }[] }): LayerRun[];
```
- `submit`: chỉ các phần có file nằm trong `changed`, theo `root`.
- `integrate` và `close`: mọi phần, cộng `system`.
- Luật kích hoạt khớp glob `changed`, hoặc khớp `goalFlag`.
- Tool có `when: 'flag:<x>'` chỉ chạy khi Goal có cờ `x`.
- Lớp nằm trong `reductions` thì vẫn trả về với `reduced: true`, để bảng ghi được. Gate không chạy lớp đó.

### Task 2: Lead thêm lớp, bớt sàn

**Files:** `src/domain/packages.ts`, `src/domain/contracts.ts` (thêm `layers?: Partial<Record<Stage, LayerId[]>>` cho gói và cho Solo proposal), `src/domain/plan.ts`, `src/app/exceptions.ts` (`floor-reduced` có `ref = <packageId>:<stage>:<layer>`)

- `lead commit` kiểm mọi lớp Lead thêm đều có trong setup của phần liên quan (Review Focus 2).
- `exception approve --kind floor-reduced` bỏ chặn từ chối của đợt 3. Ngoại lệ phải có trước lần submit thì mới có hiệu lực.

### Task 3: Gate chạy theo lớp ở ba khâu

**Files:** `src/app/gate-service.ts`, `src/app/package-service.ts`, `src/app/integration.ts`, `src/cli/commands/outcome.ts`, kèm test

- Mỗi `LayerRun` chạy trong worktree sạch, đọc kết quả theo `format`, và thành một `CheckResult` có `checkId = <part>.<layer>.<tool.id>`.
- Lớp test (`junit`, `apos-json`): xanh khi không có lỗi mới so với base. Riêng test đã khoá thì phải pass (đợt 3).
- `exit`: xanh khi mã thoát là 0.
- `sarif`: đỏ khi có finding có `level` từ mức chặn trở lên. Mức chặn mặc định là `error`, khai bằng `tool.failOn`.
- `metric`: so với `tool.threshold`, xem Task 4.
- Lớp không có test nào ở khâu đó: `unverifiable` (Review Focus 1).
- **Áp `runs`** cho lớp test (mặc định 1, setup đặt được) và cho benchmark (mặc định 3). Lệch nhau là `unverifiable`.
- `integration gate` chạy khâu `integrate` (Review Focus 5).
- `outcome close` chạy khâu `close` trên commit đóng; chỉ cho đóng khi xanh, hoặc khi mọi chỗ không xanh đều có ngoại lệ.

### Task 4: Bằng chứng phi chức năng

**Files:** `src/domain/contracts.ts` (thêm `proof: 'benchmark' | 'scan'`, cùng `benchmark: { tool: string; metric: string; op: '<'|'<='|'>'|'>='; value: number }` và `scan: { tool: string; failOn: 'error'|'warning'|'note' }`, trong đó `tool` là `<part>.<layer>.<id>` của setup), `src/domain/layer-plan.ts`, `src/app/gate-service.ts`

- Tiêu chí `benchmark` hoặc `scan` làm lớp của tool đó chạy ở khâu `close`. Lead kéo lên sớm hơn được bằng `layers`.
- Ngưỡng nằm trong **Goal**, tức anh đã duyệt. Setup không có quyền ghi đè ngưỡng của Goal.
- `goal approve` từ chối tiêu chí trỏ tới tool không có trong setup đã ghim.

### Task 5: Test chỉ gọi qua cửa đã khai (chỗ nào làm được)

**Files:** `catalog/*.yaml` (thêm `entryRule` cho mỗi stack), `src/app/test-lock.ts`

- `entryRule = { importPattern: string }`: regex lấy module được import trong file test. Python: `^\s*(?:from|import)\s+([\w.]+)`; TS: `from\s+['"]([^'"]+)['"]`.
- Lúc `tests submit` và `tests revise`: module nào được import trong test L2 mà không thuộc `stubPaths`, không thuộc thư viện test hay chuẩn (danh sách `allowImports` trong danh mục), và không thuộc chính thư mục test, thì từ chối. Lỗi phải nêu tên file và dòng.
- Stack không có `entryRule` thì bảng ghi "chưa kiểm".

### Task 6: Bảng mức bảo đảm

**Files:** Create `src/app/assurance-report.ts`; Modify `src/cli/commands/goal.ts` (`goal show <id>` in bảng), `src/ui/read-model.ts`, `src/ui/page.ts`, phần publish milestone (bảng vào tài liệu Goal được commit)

```ts
type AssuranceReport = {
  goalId: string; setup?: { version: number; parts: Record<string, string> };
  criteria: { total: number; machine: number; manual: number; byProof: Record<string, number> };
  lockedTests: { byLayer: Record<string, number>; revisions: number; autoRelocked: number; approvedWeakenings: number };
  layers: { stage: Stage; part: string; layer: LayerId; tool: string; why: string; status: 'pass'|'fail'|'unverifiable'|'reduced'|'not-run' }[];
  exceptions: { kind: string; ref: string; by: string; reason: string }[];   // by: 'human' | 'on-behalf:<..>' | 'agent:<..>'
  off: string[];        // vd "mutation: Goal không gắn cờ", "test chỉ gọi qua cửa: typescript chưa có luật"
  exitOnly: string[];   // tool chỉ có mã thoát
};
function buildAssuranceReport(state: GoalState, setup?: ProjectSetup): AssuranceReport;
function renderAssuranceText(r: AssuranceReport): string;   // giống mẫu ở spec 6.9
```
- Có dòng "agent duyệt thay: n chỗ", kèm danh sách.

### Task 7: E2E và tài liệu

- E2E thật (pytest, vitest; skip nếu máy thiếu):
  - sửa `src/ui/**` kích hoạt e2e ở khâu `submit`;
  - Lead thêm L3; bớt L2 bằng ngoại lệ do agent duyệt;
  - tiêu chí benchmark `p95_ms < 200` với script in JSON (một lần đạt, một lần trượt);
  - tiêu chí scan bằng SARIF giả;
  - Multi-WP hai gói, integration chạy L3;
  - `goal show` in bảng và khớp snapshot.
- Tài liệu: `README.md` (flow đầy đủ, các lớp, bảng mức bảo đảm), `docs/setup.md` (floor, triggers, `runs`, `failOn`, threshold), `docs/catalog.md` (`entryRule`, `allowImports`), skill `lead` (chọn lớp, bớt sàn bằng ngoại lệ), `pm` (viết tiêu chí `benchmark` và `scan`), `docs/fault-injection.md` (Review Focus 1–5).
