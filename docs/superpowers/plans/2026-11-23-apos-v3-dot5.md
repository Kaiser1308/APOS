# APOS v3 – Đợt 5: Review và công cụ AI chặn bằng test đỏ; mutation; Goal mẫu – Kế hoạch

> **Cho worker:** TDD từng task, `npm run check` xanh và commit ở cuối mỗi task. Commit đầu chép file này vào `docs/superpowers/plans/2026-11-23-apos-v3-dot5.md`. Kế hoạch sai ở chỗ đổi hành vi thì hỏi Lead.

**Goal:**
- Review (của người, LLM hay công cụ AI) chỉ chặn được một gói khi nộp kèm một test máy chạy lại được và đỏ trên commit giao. Test đó được khoá thành bằng chứng bắt buộc cho lần giao sau. Nhận xét không kèm test chỉ là góp ý.
- Mutation test chạy theo cờ của Goal, có ngưỡng điểm.
- Repo có hai Goal mẫu (TypeScript, Python) chạy trọn luồng v3 và in ra bảng mức bảo đảm.

**Spec:** `docs/superpowers/specs/2026-11-22-apos-v3-design.md` mục 6.7, 6.8, 6.4 (sửa test đã khoá), 6.9. Nền: đợt 1–4.

## Global Constraints

- Lõi không biết tên công cụ mutation nào. Lệnh lấy từ setup (danh mục: Stryker cho TS, mutmut cho Python, PIT cho Java), đọc kết quả theo định dạng `metric`.
- Không thêm runtime dependency.
- Công cụ AI không bao giờ là trọng tài (spec 6.7). Mọi bằng chứng do AI tạo ra đều đi qua đúng đường của test bình thường.

## Review Focus

1. **Test chặn đỏ vì lỗi nạp hoặc lỗi cú pháp** (không phải vì code sai): từ chối, không chặn được gói. Dùng `loadErrorPatterns` như ở khâu 2b.
2. **Test chặn cũng đỏ trên base đã khoá** (lỗi có từ trước, không do gói này gây ra): ghi nhận là finding cho Goal, nhưng không chặn gói. Ghi rõ lý do.
3. **Test chặn sửa file ngoài thư mục test**, hoặc sửa test đã khoá: từ chối. Reviewer chỉ được *thêm* test.
4. **Mutation không chạy được, hoặc chạy hai lần ra hai điểm khác nhau quá ±1 điểm:** `unverifiable`, không đỏ và không xanh.
5. **Goal mẫu chạy trên máy không có `npx`/`pytest`:** script dừng sớm với thông báo rõ thiếu gì. Không được báo đạt giả.

### Task 1: `apos review block`

**Files:** Create `src/app/review-block.ts`, `src/cli/commands/review.ts` (thay `review submit` cũ, vốn chỉ còn là ghi chú tư vấn); Modify `src/domain/transitions.ts`, `src/app/inbox.ts`

**Interfaces:**
- `apos review block <goalId> <packageId> --commit <reviewCommit> --by <reviewer> [--note <text>]`
- `reviewCommit` phải có đúng **một cha** là commit giao (gate) gần nhất của gói, và chỉ thêm file khớp `tests.paths` (Review Focus 3).
- Máy chạy các test **mới thêm** ở `reviewCommit`, theo lớp của file:
  - có test `fail`, hoặc `error` không khớp `loadErrorPatterns`: ghi `review-blocked { packageId, deliveryCommit, reviewCommit, testIds, by }`, gói chuyển `red`, lý do `blocked by review: <ids>`;
  - mọi test xanh: ghi `review-advice` (chỉ là góp ý);
  - lỗi nạp: từ chối (Review Focus 1).
- Kiểm thêm: test đó cũng đỏ trên base đã khoá thì ghi `finding-recorded kind=pre-existing` và không chặn (Review Focus 2).
- Lần submit sau của gói: commit phải chứa các file test của `reviewCommit`, và các test đó phải xanh. Chúng được thêm vào khoá (`tests-locked` có `revisionOf` và `source: 'review'`), tự khoá lại không cần duyệt, vì đây là thêm assert chứ không bớt.
- `apos review note <goalId> <packageId> --by --note`: chỉ ghi góp ý.
- Áp dụng giống vậy ở khâu integrate: `review block <goalId> --integration --commit`.

### Task 2: Công cụ AI

**Files:** `docs/catalog.md`, `.apos/skills/reviewer.md`, `.apos/skills/tester.md`

- Không cần mã mới. Viết hướng dẫn: AI sinh test thì nộp qua `tests submit` hoặc `tests revise`; AI tìm lỗi thì nộp qua `review block`.
- Probe đã loại sẵn công cụ chạy không ổn định. Thêm một ca fault-injection: một "công cụ AI" giả, mỗi lần chạy in ra kết quả khác nhau, thì probe trượt.

### Task 3: Mutation

**Files:** `catalog/*.json` (L5 mutation có `when: 'flag:mutation'`, `format: metric`, kèm đường dẫn metric của từng công cụ), `src/app/gate-service.ts`, `src/domain/layer-plan.ts`, `src/cli/commands/goal.ts` (`goal approve --flag mutation`), kèm test

- Mutation chạy ở khâu `close` khi Goal có cờ `mutation`. Lead kéo lên khâu `submit` được bằng `layers`.
- `{changed}` truyền danh sách file đã đổi so với base đã khoá, để chỉ đột biến code mới.
- Ngưỡng là `setup.mutation.minScore` (mặc định 70, sàn chặt). Tiêu chí kiểu `benchmark` của Goal có thể nâng ngưỡng, không được hạ.
- Chạy 2 lần, lệch quá ±1 điểm thì `unverifiable` (Review Focus 4).
- Bảng mức bảo đảm ghi điểm, hoặc "mutation tắt (Goal không gắn cờ)".

### Task 4: Hai Goal mẫu

**Files:** Create `examples/ts-orders/` (repo mẫu TypeScript với vitest), `examples/py-parking/` (Python với pytest), `scripts/demo-goal.mjs`, `docs/demo.md`

- Mỗi ví dụ gồm: mã nguồn ban đầu, tài liệu nguồn của Goal (`brief.md`), `goal.json` có tiêu chí Cho trước/Khi/Thì cộng một tiêu chí `benchmark`, `plan.json` (Solo), thư mục `steps/` chứa các bản vá theo thứ tự.
  - **TS:** "Đơn quá 30 ngày không huỷ được".
  - **Python:** "Ô đỗ chuyển 'đã có xe' khi cảm biến báo".
- Các bản vá trong `steps/`:
  1. test chấp nhận và stub;
  2. code lỗi (test vẫn đỏ, cộng thêm một lần sửa test đã khoá để thấy bị chặn);
  3. code đúng;
  4. một reviewer chặn bằng test đỏ;
  5. bản sửa cuối.
- `node scripts/demo-goal.mjs <example> [--keep]` chép ví dụ ra thư mục tạm, `git init`, rồi chạy APOS thật qua `dist/cli.js` (`--on-behalf "demo"` cho lệnh Human): setup draft, probe, approve → goal create, approve, select → lead propose, commit → tests submit (locked) → package submit (đỏ, vì sửa test khoá) → package submit (đỏ, vì code lỗi) → package submit (xanh) → review block (đỏ) → package submit (xanh) → outcome close → `goal show` (in bảng mức bảo đảm).
  - Mỗi bước in kết quả và kiểm mã thoát mong đợi. Sai thì thoát khác 0.
  - Thiếu công cụ thì xử lý theo Review Focus 5.
- Thêm một test vitest gọi script này (skip có điều kiện), và thêm `npm run demo:ts`, `npm run demo:py`.
- `docs/demo.md` có output thật của cả hai lần chạy.
