# APOS v3.1 – Tình huống 2: repo cũ chưa có test, Goal chụp hành vi, Goal refactor – Kế hoạch

> **Cho worker:** TDD từng task, `npm run check` xanh và commit ở cuối mỗi task. Kế hoạch sai ở chỗ đổi hành vi, hoặc nhắc tới thứ không có trong code, thì hỏi Lead trước khi tự chế.

**Goal:** APOS dùng được trên repo cũ ít hoặc chưa có test, mà không giả vờ là đang bảo đảm. Đường đi: duyệt setup với nhãn "bảo đảm thấp" → Goal `characterize` khoá hành vi hiện tại bằng test xanh → Goal `refactor` chỉ được làm trên phần đã chụp, và mọi test đã chụp phải xanh trước lẫn sau.

**Thiết kế đã duyệt:** `reports/apos-v3.1-cases-design-2026-11-23.md` mục 2. Nền: `main` a30f5bf (đã có Goal `kind`, `apos bug`, proof `stays-green`).

## Global Constraints

- Không nới luật nào cho Goal thường. Nhãn "bảo đảm thấp" chỉ thêm cảnh báo, không bỏ phép kiểm tra nào.
- Mọi quyết định "chấp nhận yếu hơn" là của Human (lệnh Human, có xác nhận) và hiện trên bảng mức bảo đảm.
- Không thêm runtime dependency. Fixture chạy được trên Windows.

## Review Focus

1. **Probe nhầm "chưa có test" với "công cụ hỏng":** chỉ coi là chưa có test khi công cụ báo đúng tín hiệu không có test (pytest mã thoát 5; vitest "No test files found"; khai bằng `noTestsPatterns`/`noTestsExitCodes` trong danh mục). Lỗi nạp, lệnh không tồn tại, mã thoát khác vẫn là trượt như cũ.
2. **Repo chưa có test mà duyệt setup không có cờ:** từ chối, nói rõ cần `setup approve --baseline-missing` (Human).
3. **Goal characterize sửa file không phải test** (ở bất kỳ commit nào của Goal): từ chối. Test đỏ trên code hiện tại: từ chối ("chụp hành vi phải xanh trên code như hiện tại").
4. **Refactor chạm file ngoài phần đã chụp:** `goal approve` (hoặc `lead commit`, chỗ nào có `paths` thì chỗ đó) từ chối, nêu tên file/glob chưa được phủ.
5. **Refactor làm đỏ một test đã chụp, hoặc xoá/sửa nó:** đỏ, như test đã khoá.
6. **Nhãn bảo đảm thấp không tự mất:** chỉ mất khi một setup version mới được duyệt mà probe thấy có test thật.

### Task 1: Probe và duyệt setup cho repo chưa có test

- Danh mục (`catalog/python.yaml`, `typescript.yaml`, `java.yaml`): thêm tín hiệu "không có test" cho lớp test (Review Focus 1). Java/JUnit không có tín hiệu rõ thì để trống, nghĩa là không hỗ trợ.
- Probe ghi kết quả lớp đó là `no-tests` (khác `pass`/`fail`).
- `setup approve`: có lớp `no-tests` thì cần `--baseline-missing`; ghi vào sự kiện duyệt `assurance: 'baseline-missing'` cùng danh sách lớp chưa có test.
- Bảng mức bảo đảm của mọi Goal ghim setup đó có dòng đầu "BẢO ĐẢM THẤP: repo chưa có test nền (<lớp>)". Inbox và `goal show` hiện như vậy. Review Focus 6.

### Task 2: Goal `characterize`

- `apos goal create --kind characterize ... --covers <glob> [--covers <glob>]`: `covers` là phần code mà Goal này chụp hành vi, nằm trong Goal nên anh duyệt khi `goal approve`.
- Mọi tiêu chí của Goal characterize mặc định proof `stays-green` (tiêu chí khác bị từ chối lúc tạo). Tiêu chí mô tả hành vi **hiện tại**, kể cả hành vi lạ; skill `apos-pm` và `apos-tester` hướng dẫn ghi hành vi lạ thành ghi chú "có thể là lỗi, mở `apos bug` sau".
- Luồng: Tester nộp test (`tests submit`): chỉ test và tests.json, xanh hai lần trên code hiện tại, rồi khoá (Review Focus 3). Không có gói code: Goal được verified khi test đã khoá và lớp khâu `close` xanh trên commit khoá; `outcome close` như thường. Nếu luồng hiện tại bắt buộc có gói, chọn cách ít đổi nhất và ghi vào PR (hỏi Lead nếu phải đổi máy trạng thái).
- `lead propose --characterize` sinh kế hoạch Solo tương ứng (giống `--bugfix`).

### Task 3: Goal `refactor`

- `apos goal create --kind refactor ... --paths <glob>...`: phần code sẽ refactor.
- `goal approve` từ chối khi có glob trong `paths` không nằm trọn trong `covers` của ít nhất một Goal characterize **đã đóng** của repo (so glob theo file thật đang có trong repo ở commit base: mỗi file khớp `paths` phải khớp một `covers`). Review Focus 4.
- Test đã khoá của các Goal characterize phủ những file đó trở thành bằng chứng bắt buộc của Goal refactor: gate ở khâu submit và close chạy chúng, mỗi test phải pass, và không được sửa/xoá (giống test đã khoá; dùng lại cơ chế khoá, không viết cơ chế thứ hai). Review Focus 5.
- Goal refactor không cần tiêu chí mới; có thì chỉ được `stays-green`. Kiểm kê (inventory) không được hụt như luật hiện có; cờ `mutation` dùng được.
- Bảng mức bảo đảm: "giữ nguyên hành vi: n test chụp từ <GOAL-…>, xanh trước trên <base>, xanh sau trên <commit>".

### Task 4: Demo, e2e, tài liệu

- Ví dụ `examples/py-legacy/` (pytest, repo **chưa có test**, một module có hành vi lạ). `scripts/demo-goal.mjs` chạy: setup draft → probe (`no-tests`) → `setup approve` không cờ bị từ chối → có `--baseline-missing --on-behalf demo` → Goal characterize (test đỏ bị từ chối, test xanh bị khoá) → close → Goal refactor có `paths` ngoài `covers` bị từ chối → `paths` đúng → refactor làm vỡ hành vi (đỏ) → refactor đúng (xanh) → close → `goal show`. Thêm `npm run demo:legacy`, test vitest gọi nó (skip có điều kiện).
- E2E vitest thật: một ca probe TypeScript "No test files found" ra `no-tests`.
- Tài liệu: `README.md` (đi vào repo cũ), `docs/setup.md` (`--baseline-missing`, tín hiệu không có test), `docs/catalog.md`, `docs/demo.md` (output thật), skill `apos-pm`, `apos-lead`, `apos-tester`. Danh sách lệnh Human (khối AGENTS.md có test đối chiếu) cập nhật nếu thêm lệnh Human.
- Mở PR vào `main`: bảng task, quyết định nhỏ, bằng chứng (`npm run check`, output demo), dòng Generated with Claude Code.
