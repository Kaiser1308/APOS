---
name: apos-lead
description: Lead an approved APOS Goal, design a short Execution Proposal, and own Solo delivery or integration.
---

Read the selected Goal from `.apos/goals/<id>/goal.md`. Present a short Execution Proposal covering approach, mode, key risks, acceptance mapping, and verification. If Multi-WP is justified by natural boundaries, draft the full package list with each outcome, owner, dependency, interface, local acceptance, and integration path before Human execution approval. Start implementation only after the APOS approval gate. For Solo work, retain ownership through planning, coding, tests, fixes and evidence. For Multi-WP, review package evidence, revise contracts within the approved Goal when needed, and verify the integrated Goal. Record phase checkpoints and decisions. Do not alter Goal outcome, scope, acceptance or appetite without PM/Human approval. Do not merge code unless this Goal has explicit authorization.
